# 多语言本地化

> 基线：NewLife.Core 12 编译期词表｜运行时 31 种译文语言 + 英文源文（32 个区域）｜消息以英文为源文，实体元数据以项目母语为源文

## 1. 语言分层

本库按 NuGet 下载量分层维护运行时词表：下载量较高的核心组件对齐 NewLife.Core 的 31 种语言，其余组件维护 11 种语言（与 README 读者一致）。缺失译文在运行时自动回退英文，新增语言不需要改代码。

> 当前消息基线共 375 条词条，XCode、各数据库驱动与 XCodeTool 的运行时消息已全部英文化（`Tools/Scripts/check-english-exceptions.ps1` 全仓通过，含变量赋值与跨行消息扫描）。**31 种译文语言的消息词表均已提供完整译文**（备份恢复、实体工厂、地址合并、驱动与数据访问日志、生成器进度、驱动诊断与设置页字段说明全覆盖），运行时不再有英文占位；此外 XCode 内置实体与字段的 176 条元数据（含实体/字段显示名、描述、字段分组与程序集标题/描述）也已补齐 31 种译文，下游项目允许只补部分语言，缺失回退源文。`Tools/Scripts/check-locales.ps1 -RequireTranslated` 会在 CI 中阻止新增未翻译的消息词条，同时校验源码中的 `L.T`、异常消息、`XTrace.WriteLine`、`Log.Info`、`WriteLog` 与带前缀日志均已有对应词条。

## 2. 词表文件

- `XCode/Locales`

- 文件名即 BCP 47 语言代码。消息以英文为源文与兜底，**不需要** `en.yml`；`en.yml` 只承载「中文源文的实体元数据」的英文译文（见 4.3）。
- 消息键为**英文原文**，必须与代码字符串逐字一致（含空格与标点）；占位符 `{0}` 与格式说明符 `{1:n0}` 必须与英文一致。元数据键为**项目母语原文**（如 `"用户": "User"`），必须与 `Model.xml` 的 `DisplayName`/`Description` 逐字一致。
- 词表由 NewLife.Core 包内的源生成器在编译期读取并生成压缩语言表，NativeAOT 下同样可用。

## 3. 新增一条消息

1. 代码中写英文源文：`throw new XException("Session {0} is closed.", sessionId);`，日志直接写英文模板（`Logger.Format` 自动翻译）。
2. 在全部语言文件的同一位置补齐该键；遗漏只回退英文，不会编译失败。
3. 运行校验脚本确认键集合、占位符与格式说明符一致。

### 3.1 带实例前缀的日志

实例前缀（如 `EntityCache<User>`、`SingleCache<User>`）随对象变化，**不能与消息模板拼成一串再查表**，否则永远匹配不到词条。统一使用 NewLife.Core 提供的前缀日志扩展，先按日志语言翻译并格式化原始模板，再拼接前缀：

```csharp
// ✅ 前缀在翻译之后拼接
XTrace.Log?.InfoPrefixed(LogPrefix, "Updating (#{0}), reason: {1}", times, reason);
Log?.ErrorPrefixed(LogPrefix, "Failed to load [{0}].", tableName);

// ❌ 整串前缀参与查表，译文必然缺失
XTrace.WriteLine(LogPrefix + "更新（第{0}次），原因：{1}", times, reason);
```

需要自行组装消息时，用 `Logger.FormatMessage(log, format, args)` 取得已翻译并格式化的消息后再拼前缀。日志语言由 `Localization.LogCulture` 控制，与异常/界面使用的 `Localization.Culture` 相互独立。

没有实例前缀的普通日志继续用 `XTrace.WriteLine("...", args)`，由 `Logger.Format` 自动翻译；只有前缀随实例变化时才用 `*Prefixed`。**不要**为了“翻译”写成 `InfoPrefixed(null, ...)`——空前缀与 `XTrace.WriteLine` 等价，却会跳过 `XTrace` 首次写日志的版本输出，并提前把模板格式化成整串交给下游日志实现。

### 3.2 程序集标题与描述

沿用 NewLife.Core 的三段式（英文源文 + 词表 + 展示层翻译）：

- csproj 的 `AssemblyTitle` 与 `Description` 一律写**英文源文**，并把同一字符串作为 key 写入 `XCode/Locales`；中文给译文，其余语言填英文原文。
- NuGet 包元数据不随界面语言切换：英文 `Description` 供反射使用，中文营销文案放 `PackageDescription`，保持中英混排。
- 展示处（控制台横幅、管理面板、服务注册等）调用 `L.T(value)` 即可本地化，元数据本身与配置值保持英文。
- 品牌名（`NewLife`、`XCode`、`XTrace`、`Cube`、`Stardust`）**不译**，也不单独入表；含品牌的产品全名可以整条入表（如 `XCode Super ORM Middleware` → `XCode超级ORM中间件`）。

## 4. 校验

脚本与 NewLife.Core 一致放在 `Tools/Scripts`，按「上两级」定位仓库根目录。

```powershell
# 词表一致性（-RequireTranslated 要求所有语言均已翻译，无英文占位）
# 词表目录存在 metadata-keys.json 时自动识别为元数据键；-MetadataSourceDir 额外扫描 [DisplayName]/[Description]/[Category] 特性
pwsh -File Tools/Scripts/check-locales.ps1 -LocaleDir XCode/Locales -SourceDir "XCode,XCodeTool" -RequireTranslated -MetadataSourceDir XCode

# 运行时消息必须为英文（调用点不得含 CJK）
pwsh -File Tools/Scripts/check-english-exceptions.ps1
```

CI 的 localization job 会执行上述两个脚本，任一失败即阻断合并；元数据键可只覆盖部分语言，缺失回退源文。孤儿键扫描覆盖 `.cs` 与 `.csproj`，程序集标题/描述写在 csproj 中同样算词表源文；`UI language. Values:` 词条还会校验语言代码清单是否完整。

单元测试 `XUnitTest.XCode/LocalesCoverageTests` 同时加载源生成器注册的运行时词表，逐键校验 31 种语言均有非英文占位译文且占位符一致（375 条消息键，元数据键按规范允许回退英文），并要求「已翻译的元数据键在 31 个词表中不缺不漏」；`EntityMetadataLocalizationTests` 校验实体与程序集元数据的实际翻译。断言具体译文前必须固定 `Localization.Culture`；不变全球化模式（`DOTNET_SYSTEM_GLOBALIZATION_INVARIANT=1`，龙芯 CI 使用）下具名区域性不可用，相关用例按英文兜底跳过。

### 4.1 源码消息覆盖

`check-locales.ps1` 默认还会扫描源码中的 `L.T(...)`、`XCodeException/XException/EntityException` 构造、`XTrace.WriteLine(...)`、`Log?.Info(...)`、`WriteLog(...)` 与 `*Prefixed(...)` 字面量，要求每条消息都能在基准词表中找到对应键，防止“代码已本地化、词表漏条目”导致运行时静默回退英文。纯符号型诊断（如 `[{0}/{1}] {2}`、`Tran.Begin {0} {1}`、`CreateSplit: ...`）列在 `-AllowMissingMessage` 中，不参与翻译；确需跳过整项检查时可传 `-SkipMessageCheck`。

`-SourceDir` 支持逗号分隔的多个目录；通过 `pwsh -File` 调用时必须整体加引号（`-SourceDir "XCode,XCodeTool"`），否则 PowerShell 会把整串当作一个路径。

### 4.2 配置页字段

`XCodeSetting` 的 `[DisplayName]`/`[Description]`/`[Category]` 属于运行时界面文案：Cube 的 `DataField.Localize` 会按当前语言调用 `L.T` 翻译后展示。因此源文一律写英文（如 `[Description("Output SQL. Whether to output SQL statements, enabled by default")]`），并在全部语言词表中补齐译文；首个句号前的内容作为字段标题，其余作为说明。`Cache` 等在所有语言中同形的词由 `check-locales.ps1` 的 `-AllowSameValue` 放行。

### 4.3 实体、枚举与模型元数据保持母语

实体特性（`[BindTable]`/`[BindColumn]`/`[DisplayName]`/`[Description]`/`[Category]`）、模型元数据（`XField`/`XIndex`/`XTable`/`TableItem`/`DatabaseType` 等类型的属性与枚举项）、生成器选项以及 `Member.xml`、`Model.xml`、`Ext.xml` 的 `Description`/`DisplayName`，描述的是开发者建立的表结构，**保持项目母语，不强制改写成英文**。这些文案继续作为生成实体注释、字段显示名与数据库注释的来源；元数据本身不参与日志、审计和原始数据输出。

Cube 等 UI 消费方在渲染期按源文查词表：`Model.xml` 为简体中文时，`Locales/<culture>.yml` 的 key 就是中文原文。实体与字段的 `DisplayName`（短名，如 `"名称": "Name"`）、`Description`（整句，如 `"名称。显示名称": "Name. Display name"`）与 `Category`（字段分组，如 `"登录信息": "Login Info"`）**都可以入表**。可选键清单登记源码中的全部元数据键（当前 293 条，含模型与生成器描述），其中 176 条（实体/字段显示名、描述、分组与程序集标题/描述）已补齐 31 种译文。

元数据词条由数据类库或 XCode 自己的 `Locales` 携带；`metadata-keys.json` 登记这些键，`check-locales.ps1` 发现同目录清单时自动识别：下游项目允许只补部分语言，缺失回退源文。清单由 `collect-metadata-keys.ps1` 从模型文件、生成代码特性或项目文件生成（`-All` 输出源码中扫描到的全部键，缺省只输出「部分语言缺失」的键并保留清单已有条目；`-OutFile` 导出覆盖矩阵）：

```powershell
pwsh -File Tools/Scripts/collect-metadata-keys.ps1 -Model XCode/Membership/Member.xml -All -OutFile .tmp/metadata-coverage.csv
```

代码生成器不为实体类与控制器额外写入 `[DisplayName]`/`[Description]`：实体沿用 `[Description]`（表/字段描述），魔方扫描菜单时若控制器上找不到这两个特性，会回退到泛型实体类；开发者手写的控制器特性文本同样可作为元数据键入表，下游用 `-MetadataSourceDir` 指向 Web 项目目录即可扫描。

### 4.4 不在运行时消息范围

以下内容保持原值，不参与词表翻译：

- 持久化数据与种子数据：角色/部门/地区/菜单/租户名称、日志动作名（如“添加”“修改”）等。这些值会写入数据库并参与匹配，翻译会破坏既有数据；菜单名可在**渲染期**翻译，但落库值保持源文。
- 代码生成产物：生成实体代码中的 `#region`、数据字典 HTML 表头、生成代码注释等模板文本。
- 数据库内部标识：SQL 列别名、正则分组名、协议字段名等非用户可见字符串。
