# 实体字段命名规范

> 适用范围：NewLife.XCode 内置实体、使用 XCode 建模的业务项目。
> 相关：NewLifeX/NewLife.Cube#177

## 1. 命名约定

| 场景 | 统一写法 | 示例 |
|------|---------|------|
| 主键 | `Id` | `User.Id`、`AccessRule.Id` |
| 外键/关联 | `XxxId` | `UserId`、`ParentId`、`RoleId` |
| 审计字段 | `CreateUserId` / `UpdateUserId` | — |
| 链路字段 | `TraceId` | — |

**禁止**：

- 新增 `ID` 全大写后缀（`CreateUserID`、`ParentID` 等）
- 同一张表出现仅大小写不同的字段（`Id` 与 `ID`）。XCode 在实体初始化与反向工程阶段都会直接抛出 `XCodeException`，不提供兼容。

历史实体（`XCode.Membership`、`NewLife.Cube.Entity`）已完成一次性改名，旧属性名以过时别名保留（见第 5 节），第三方项目升级时按编译警告逐项修正即可；字段查找与比较本身不区分大小写，字符串形式的字段名无需同步。

## 2. NameFormats 语义

`NameFormats` 同时控制**大小写转换**与**是否强制加引号**：

| 值 | 大小写转换 | 引号 | 语义 |
|----|-----------|------|------|
| `Default` | 无 | 按方言 | 跟随数据库默认（`DefaultNameFormat`） |
| `None` | 无 | 不加（仅关键字/特殊字符） | 交给数据库折叠大小写 |
| `Upper` | 全大写 | 不加 | — |
| `Lower` | 全小写 | 不加 | — |
| `Underline` | 下划线小写 | 不加 | — |
| `Exact` | 无 | **强制加** | 物理名称逐字精确、区分大小写 |

生效优先级：

1. 连接字符串 `NameFormat=Exact`（仅作用于该连接）
2. `XCodeSetting.NameFormat`（全局）
3. 数据库默认 `DefaultNameFormat`（如 PostgreSQL / VastBase 为 `Underline`，KingBase / HighGo 为 `Exact`）

Model.xml 中的 `NameFormat` 只作用于代码生成器（`xcode`），不影响运行时 SQL。

## 3. 各数据库行为

| 数据库 | 默认格式 | 说明 |
|--------|---------|------|
| PostgreSQL / VastBase | `Underline` | 物理列名为 `id` / `create_user_id` |
| KingBase / HighGo | `Exact` | 标识符加双引号，物理名逐字保留 |
| MySQL / SQLite | `None` | 列名不区分大小写 |
| Oracle / 达梦 / DB2 | `None` | 不加引号时折叠大写 |
| SQL Server | `None` | 大小写敏感度由数据库排序规则决定，`_CS_` 时建议显式配置 `NameFormat=Exact` |

## 4. 改名迁移

字段改名后，旧库中的物理列名仍是旧值。迁移行为取决于有效命名格式：

- **`Exact` 且列名仅大小写不同**：反向工程使用精确比较，`Migration >= On` 时自动生成 `ALTER TABLE ... RENAME COLUMN`（SQL Server 使用 `sp_rename`），无需手工脚本。
- **其它格式**：比较忽略大小写，不产生 DDL。数据库自身折叠大小写时（如 PostgreSQL 的 `Underline`、MySQL 的列名规则），改名前后的物理名称本来就相同。
- **数据库同时存在仅大小写不同的两列**：XCode 不支持该结构，启动时抛异常。

## 5. 兼容别名

内置实体（`XCode.Membership` 与 `NewLife.Cube.Entity`）改名时，在 `*.Biz.cs` 的 `#region 兼容别名` 中保留旧名称：

| 旧写法 | 兼容形式 | 说明 |
|--------|---------|------|
| `user.ID`、`user.CreateUserID` | 过时属性别名 | 读写映射到新属性，四类序列化均忽略 |
| `Role.FindByID(...)`、`User.FindAllByRoleID(...)` | 过时静态转发方法 | 直接调用生成器产出的 `FindById` / `FindAllByRoleId` |

```csharp
[Obsolete("请使用 FindById")]
public static Role? FindByID(Int32 id) => FindById(id);
```

**保留自定义实现的例外**（不转发，避免行为回退）：

| 方法 | 原因 |
|------|------|
| `Area.FindByID` | 实体缓存只加载省市县，街道级编号必须走单对象缓存 |
| `Area.FindAllByParentID` | 四级地区使用专属缓存，避免反复查库 |
| `UserToken.FindByID`、`UserOnline.FindByID` | 令牌与在线记录要求绕过实体缓存取最新数据 |
| `IRole`/`IMenuFactory`/`IManageProvider` 的 `FindByID` | 接口成员没有对应新名称，改接口会打断自定义实现，且 net45 目标不支持默认接口实现 |

```csharp
[Obsolete("请使用 Id")]
[XmlIgnore, IgnoreDataMember, ScriptIgnore]
#if NET5_0_OR_GREATER
[System.Text.Json.Serialization.JsonIgnore]
#endif
public Int32 ID { get => Id; set => Id = value; }
```

- 别名属性没有 `[DataObjectField]`，不进入 `Fields` 与 `Table.Columns`，不参与映射与序列化；`Table.FindByName("ID")` 仍然命中真实字段 `Id`
- 同一张表禁止仅大小写不同的真实字段，因此别名不会与生成字段冲突；索引器精确命中别名 `entity["ID"]`，其余大小写返回 `null` 而不是抛异常
- 覆盖范围为属性与查询方法；**`_`/`__` 字段名快捷方式不提供别名**，`User._.ID`、`User.__.ID` 需直接改用 `Id`；接口成员（`IUser.Id` 等）和模型类（`UserModel`）同样不提供别名
- 新代码一律使用新名称，`[Obsolete]` 会在编译期提示

## 6. 常见问题

**Q：能不能只改属性名、物理列名保持不变？**

可以。Model.xml 中同时写 `Name="Id"` 与 `ColumnName="ID"`，并设置 `NameFormat=Exact` 以保留仅大小写差异（否则 `xcode` 回写时会丢失 `ColumnName`）。本项目未采用该方式，存量实体已统一改名。

**Q：MySQL 能否配置成大小写敏感？**

不能。MySQL 的**列名**在所有平台上都不区分大小写，`lower_case_table_names` 只影响表名与库名。

**Q：SQL Server 能否靠加引号实现大小写敏感？**

不能。标识符比较跟随数据库排序规则，`[Id]` 与 `[ID]` 在 `_CS_` 规则下不同、在默认 `_CI_` 规则下相同。
