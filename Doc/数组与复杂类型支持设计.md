# XCode 数组与复杂类型支持设计

> 状态：P1+P2 已实施（P3 待定） | 日期：2026-11-23 | 触发场景：Presto/Hive 表出现 `array(varchar)`、`array(bigint)`

## 1. 结论

**值得支持，但只做“只读 + 有限类型 + 显式开启”，不做全量数组语义。**

理由：

- 需求真实存在。Presto/Trino、Hive、ClickHouse、PostgreSQL 都有数组列；当前只能降级为 JSON 字符串，丢类型、无法过滤、界面只能看原文。
- 当年 PG 数组方案做了一整月仍不稳定，根因是**一次把读、写、DDL、跨库迁移、表达式、缓存、代码生成全做了**，每层都有特例，测试面失控。
- 把范围压到“只读 + 少量元素类型 + 不做迁移”，工作量可控、可测、可回退；写入与迁移以后单独立项。

## 2. 目标与非目标

### 目标

1. 反向工程能把 `array(varchar)`、`array(smallint)`、`array(bigint)`、`array(integer)`、`array(double)`、`array(decimal(p,s))`、`array(boolean)` 识别为 `String[]`、`Int16[]`、`Int64[]`、`Int32[]`、`Double[]`、`Decimal[]`、`Boolean[]`。
2. 实体属性可用对应数组类型，支持 `FindAll`/`FindCount` 读取。
3. `DbTable`/`DataRow` 能承载数组值（XCode 归一化为强类型数组），文本序列化不承诺 JSON。
4. 支持“包含”查询：Presto `contains(arr, x)` 与 PG `@>` 按方言生成。

### 非目标（本阶段明确不做）

- 数组写入、批量写入、`Insert`/`Update`（Presto 连接器大多只读）。
- DDL 建表、加列、跨库迁移。
- 嵌套数组（`array(array(int))`）、`map`、`row`（继续按 JSON 字符串处理）。
- 数组元素级索引表达式（`arr[1]`、`arr[1:2]`）。
- 缓存主键比较的深度语义（见 §6 风险）。

## 3. 现状盘点

| 项目 | 现状 |
|------|------|
| 驱动 | `NewLife.Presto` 支持 `ComplexTypes=String`（默认，JSON 文本）与 `ComplexTypes=Structured`（array→`Object[]`、map→`IDictionary`、row→`Object[]`）。XCode 连接串加 `Arrays=On` 时自动补 `ComplexTypes=Structured` |
| 模型 | `IDataColumn.DataType` 为 `Type`。`Arrays=On` 时一层数组映射为 `String[]`/`Int16[]`/`Int32[]`/`Int64[]`/`Double[]`/`Decimal[]`/`Boolean[]`；其余继续降级 `String` |
| 扩展点 | `IDataColumn.ItemType`、`BindColumnAttribute.ItemType` 仅作 `date`/`html`/`percent` 等展示提示，不复用为元素类型 |
| 读写 | `DbSession.Query` 走 `DbTable.Read(IDataReader)`；`PrestoSession.OnFill`/`QueryAsync` 把数组单元格归一化为强类型数组，map/row 还原为 JSON 文本 |
| 历史教训 | PG 数组支持因范围过大停摆，代码未合入主线；本次限定只读 + 显式开关 |

## 4. 类型映射

| 数据库类型 | CLR 类型 | 备注 |
|-----------|---------|------|
| `array(varchar)` / `text[]` | `String[]` | 元素无长度信息，按 `-1`；`varchar(n)` 取 n |
| `array(char(n))` | `String[]` | 缺省长度 1 |
| `array(smallint)` / `int2[]` | `Int16[]` | |
| `array(bigint)` / `int8[]` | `Int64[]` | |
| `array(integer)` / `int4[]` | `Int32[]` | |
| `array(double)` / `float8[]` | `Double[]` | |
| `array(decimal(p,s))` / `numeric[]` | `Decimal[]` | 精度取元素声明 |
| `array(boolean)` / `bool[]` | `Boolean[]` | |
| `array(date/timestamp)` | **不支持**，降级 String | 时间元素格式差异大，先不做 |
| `array(real/tinyint/varbinary)` | **不支持**，降级 String | 无对应 `ValidHelper` 数组转换 |
| `array(array(x))`、`map`、`row` | **不支持**，降级 String | 保持 JSON 文本 |

判定顺序：`DataType = typeof(T[])`，元素类型由 `DataType.GetElementType()` 获取，元素原始类型从 `RawType`（`array(varchar)` / `varchar[]`）解析。**不新增 `ItemDataType` 属性**，避免 `IDataColumn` 接口破坏性变更与 `ItemType` 语义重载。

## 5. 分层设计

### 5.1 元数据

- `PrestoMetaData` 解析 `data_type` 为 `array(...)` 时，用 `PrestoArray.TryGetElementType` 按白名单映射元素类型，再 `MakeArrayType()`。
- 元素精度/长度：`decimal(p,s)` 取 p/s；`varchar(n)` 取 n，无长度按 `-1`；不支持的元素按 `-1`。
- 反向工程输出 Model.xml：`<Column Name="IdList" DataType="String[]" RawType="array(varchar)" />`。
- 由连接串开关 `Arrays=On` 控制，默认关闭；关闭时保持现有的 array → String 降级逻辑。

### 5.2 实体与代码生成

- 属性类型 `String[]`、`Int16[]`、`Int32[]`、`Int64[]`、`Double[]`、`Decimal[]`、`Boolean[]`。
- 生成 `BindColumn(..., RawType = "array(varchar)")` 保留元素原始类型，不再写 `ItemType`。
- 索引器 setter 对数组生成 `ValidHelper.ToStringArray`/`ToInt16Array`/`ToInt32Array`/`ToInt64Array`/`ToDoubleArray`/`ToDecimalArray`/`ToBooleanArray`，不再拼出 `ToString[]Array`。
- 实体 `CloneEntity` 对数组字段做 `Array.Clone()`；`CheckEqual` 早已按内容比较。
- 序列化：`System.Text.Json` 原生支持数组；Core 的 `BinaryList` 已支持 `T[]` 二进制编解码。

### 5.3 查询与表达式

- 已实现 `FieldItem.ArrayContains(value)`：Presto/Trino 生成 `contains(arr, x)`，PostgreSQL/VastBase 生成 `arr @> ARRAY[x]::类型[]`。
- 明确不支持对数组列使用 `==`、`OrderBy`、`GroupBy`；需要时改用 `ArrayContains` 或原生 SQL。
- `FindCount` 复用同一 SQL 生成器，无需额外实现。

### 5.4 参数绑定

- Presto：`ArrayContains` 直接生成 `contains(arr, 'x')` 字面量，不经过参数绑定。
- PG：`arr @> ARRAY['x']::varchar[]`，同样使用经过转义的字面量。
- 写入路径（`Insert`/`Update`）遇到数组字段直接抛 `NotSupportedException`，避免驱动绑定不支持的类型。

### 5.5 缓存

- `Entity<T>.CloneEntity` 对数组字段深拷贝，避免缓存对象共享可变数组。
- 数组字段本阶段不参与缓存键；大数组建议关闭 `Arrays` 或改用业务标量字段。

### 5.6 Cube / 展示

- Cube 列表默认走 `val + ""`，数组会显示为 `System.String[]`；已由 Cube 的 `ViewHelper.FormatValue` 统一改为 JSON 展示，表单中数组字段自动只读。
- 编辑页只读；不做数组编辑器。
- 限制：`DAL.Select` 的 DataSet/DataAdapter 路径不做数组归一化，数组列保持 `Object[]`；实体查询与 `DbTable` 查询路径已归一化。

## 6. 风险与回退

| 风险 | 说明 | 缓解 |
|------|------|------|
| 序列化兼容 | 旧模型/旧缓存没有数组字段，重新生成实体后字段类型变化 | 关闭 `Arrays` 即回归字符串；数组字段不参与缓存键 |
| 缓存在内存放大 | 大数组（上千元素）驻留缓存 | 超过阈值（如 10k 元素）降级字符串 |
| 表达式误用 | 用户对数组做排序/等值 | 明确抛错并给示例 |
| 跨库迁移 | 模型含数组时迁移到无数组库 | 迁移前校验并拒绝 |
| 驱动差异 | `ComplexTypes=String/Structured` 返回不同 | 只在 Structured 下启用强类型数组，String 模式仍降级 |

回退：所有数组能力由 `Arrays=On` 控制，关闭后行为与现在完全一致（JSON 字符串）。

## 8. 测试策略

- 离线：类型映射与长度/精度、Model.xml round-trip、代码生成 setter、数组转换/JSON 回退、克隆深拷贝、`ArrayContains` 方言 SQL。
- 真库：Presto `array(varchar)`/`array(bigint)`（现成表 `default.group_agg_test`）；PG `text[]`/`int8[]` 临时表。
- 缓存：数组字段内容相等；克隆后互不影响。
- 回归：无数组模型行为零变化（开关关闭）。
