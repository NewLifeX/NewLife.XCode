> 日期：2026-11-21 · 环境：Windows + WSL2 Ubuntu 24.04（WSL 内 Docker）

## 二、启动与停止

```powershell
# Windows 进程：VictoriaMetrics、InfluxDB 1.8/2.7
C:\X\LocalDatabases\start-windows.ps1
C:\X\LocalDatabases\stop-windows.ps1
```

```bash
# WSL：HBase + OpenTSDB、IoTDB、GreptimeDB、InfluxDB 3、CrateDB（Docker）
sudo systemctl start localdb
sudo systemctl status localdb
sudo systemctl stop localdb

# Prometheus、Presto、Trino、Firebird、TDengine 由各自 systemd unit 管理
sudo systemctl status prometheus presto trino firebird3.0 taosd taosadapter

# ClickHouse、CrateDB、CockroachDB、QuestDB 由 Docker 容器常驻（--restart unless-stopped）
docker ps --filter name=clickhouse
docker start clickhouse
```

DuckDB 是嵌入式数据库，无需启动服务；测试项目引用 `DuckDB.NET.Data.Full` 后直接创建库文件。

`localdb.service` 已 enable，脚本幂等：端口已监听时不会重复拉起。unit 配置了 `KillMode=none`，避免 oneshot 脚本退出时把子进程一起清理；`Wants=docker.service` 保证 Docker 先启动。Docker 与 `cratedb` 容器均配置开机自启。脚本源码位于 `C:\X\LocalDatabases\wsl-start-all.sh` / `wsl-stop-all.sh`，WSL 内安装到 `/opt/localdb/`。

### WSL 保活

WSL 默认在无客户端连接后自动关机，数据库进程会随之退出。已做两项处理：

- `C:\Users\Stone\.wslconfig` 增加 `vmIdleTimeout=86400000`（原文件备份为 `.bak-20261121`）。
- 注册表 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 增加 `LocalDatabasesKeepAlive`，登录时通过 `C:\X\LocalDatabases\keepalive.vbs` 隐藏运行 `wsl -d Ubuntu-24.04 -- bash -lc "sleep infinity"` 保持会话。

## 五、真库测试发现并修复的问题

1. **InfluxDB 2.x 元数据查询失败**：Flux 使用字面量 `v.bucket`，且 `import` 脚本被自动拼到 `from(bucket) |> ` 管道后面。改为取连接串 Bucket，并对 `import` 开头的脚本跳过自动拼接。见 [InfluxDB.cs](../XCode/DataAccessLayer/Database/InfluxDB.cs)、[InfluxDBCommand.cs](../XCode/InfluxDB/InfluxDBCommand.cs)。
2. **InfluxDB CSV 解析不兼容 CRLF**：Windows 服务端返回的行尾 `\r` 粘在列名上，导致 `_value` 找不到。构造读取器时统一换行符。见 [InfluxDBDataReader.cs](../XCode/InfluxDB/InfluxDBDataReader.cs)。
3. **InfluxDB 3 查询失败**：`/api/v3/query_sql` 只接受 GET，原来的 POST 无请求体被服务端拒绝。非 Flux 查询改用 GET。见 [InfluxDBConnection.cs](../XCode/InfluxDB/InfluxDBConnection.cs)。
4. **GreptimeDB/CrateDB 无法建立连接**：Npgsql 默认加载 `pg_catalog` 类型并执行 `DISCARD ALL`，协议兼容层不支持。PostgreSQL 提供者按别名自动追加兼容选项。见 [PostgreSQL.cs](../XCode/DataAccessLayer/Database/PostgreSQL.cs)。
5. **真库探测无法识别 URL 形式的 Server**：`[LiveDatabaseFact]` 把 `http://host:port` 整体当主机名。补充 URL 解析。见 [LiveDatabaseFactAttribute.cs](../XUnitTest.XCode/DataAccessLayer/LiveDatabaseFactAttribute.cs)。
6. **Trino 命令拿不到服务地址**：官方 `TrinoCommand` 在构造时绑定连接，工厂用临时连接创建命令后 XCode 不再替换，导致 `Invalid server URL`。工厂现在把最终连接串注入临时连接；同时 Presto/Trino 只支持单结果集，去除 `NextResult` 与 `DataTable.Load`。见 [Presto.cs](../XCode/DataAccessLayer/Database/Presto.cs)。
7. **Firebird 远程 Unix 路径被改写**：`ResolveFile` 把 `/var/lib/...` 解析成 `C:\var\lib\...`，远程库不可用；现在保留服务端绝对路径。另修正 Firebird 要求 `DEFAULT` 位于 `NOT NULL` 之前的语法。见 [Firebird.cs](../XCode/DataAccessLayer/Database/Firebird.cs)。
8. **MonetDB 连接串与结果集**：驱动只认 `Username`，提供者把 `User`/`Uid` 映射过去；驱动未实现 `GetValues`，会话改为逐列装配结果集。见 [MonetDB.cs](../XCode/DataAccessLayer/Database/MonetDB.cs)。
9. **测试项目补齐驱动引用**：新增 `Trino.Client.ADO`、`FirebirdSql.Data.FirebirdClient`、`MonetDb.Mapi`、`ClickHouse.Client`、`DuckDB.NET.Data.Full`，并显式引用新版 `Microsoft.Extensions.Logging.Abstractions`，避免 MonetDB 传递依赖的 1.1.2 与 Npgsql 冲突。
10. **TDengine 3.x HTTP 响应结构变化**：3.x 的 `column_meta` 是 `[列名, 类型, 长度]` 三元数组且不再返回 `head`，`SHOW TABLES` 也不含 `stable_name`；同时 DDL 返回 `affected_rows=0`，不能按影响行数判断建库成功。驱动改为读取 `column_meta`、按 `affected_rows` 取影响行数，元数据改用 `DESCRIBE` 固定列序，并重写建删库成功判定。见 [TDengineDriver.cs](../XCode/TDengine/TDengineDriver.cs)、[TDengineDataReader.cs](../XCode/TDengine/TDengineDataReader.cs)、[TDengine.cs](../XCode/DataAccessLayer/Database/TDengine.cs)。
11. **DuckDB 内存库与类型映射**：文件型基类会给 `:memory:` 创建非法空文件，DuckDB 元数据也缺少类型映射导致反向工程空引用。改为内存库跳过建文件、DuckDB 自行建库文件，并补齐 `DataTypes`；测试改用文件库，避免每个 `:memory:` 连接各自独立。见 [FileDb.cs](../XCode/DataAccessLayer/Common/FileDb.cs)、[DuckDB.cs](../XCode/DataAccessLayer/Database/DuckDB.cs)。
12. **ClickHouse 7.x 工厂类名变更**：`ClickHouse.Client` 7.x 的工厂类型改为 `ClickHouseConnectionFactory`，按旧名加载会一直提示缺少驱动。提供者先按新名加载并兼容旧名。见 [ClickHouse.cs](../XCode/DataAccessLayer/Database/ClickHouse.cs)。
13. **VictoriaMetrics 异步导入**：导入接口返回成功时数据尚未可见，用例改为轮询等待，避免偶发失败。见 [ProtocolAliasTests.cs](../XUnitTest.XCode/DataAccessLayer/ProtocolAliasTests.cs)。
14. **CockroachDB 时钟偏移**：WSL 与 Windows 主机存在约 1 秒时钟漂移，单节点启动需 `--max-offset=5s`，否则 SQL 连接报 `remote wall time is too far ahead`。

## 六、限制与注意事项

- **CrateDB**：Docker 容器监听 15432（PG）与 4200（HTTP）；写入为近实时，验证脚本在建表写入后执行 `REFRESH TABLE` 再查询。数据保存在 Docker 卷 `cratedb_data`。
- **CockroachDB**：单节点 `--insecure`，启动参数带 `--max-offset=5s` 以容忍 WSL 时钟漂移；PG 端口 26257，控制台 8089。
- **QuestDB**：PG 端口 8812、HTTP 9001，默认账号 `admin/quest`；`CREATE TABLE` 不支持主键约束，测试按普通列建表。
- **ClickHouse**：HTTP 8123、原生 9000；容器必须设置用户名密码，本机 `default/clickhouse`。测试只读实例信息与元数据，不覆盖 MergeTree 写入延迟。
- **TDengine**：3.x 已移除 `DAYS/BLOCKS/UPDATE` 建库参数，测试统一用 `KEEP 365`（2.x/3.x 均兼容）；`QueryTest` 依赖预置 20 行历史数据，默认跳过。
- **DuckDB**：嵌入式，无服务端；每个 `:memory:` 连接是独立数据库，跨连接场景必须用文件库。测试库文件 `Bin/UnitTest/Data/duckdb_test.duckdb` 可随时删除重建。
- **MongoDB**：提供者是文档模型，不提供 ADO.NET 连接（`Factory` 为空），真库连接不在支持范围，未纳入本机验证；实体写入需应用侧注册 `IMongoDocumentWriter`。
- **Presto / Trino**：只读联邦查询，无事务、无自增、不支持自动建表；Trino 官方驱动单查询只允许一个结果集。
- **Firebird**：远程连接时 `Database` 保留服务端路径（Unix 绝对路径不再按本机解析）；本机数据库 `SYSDBA/masterkey`。
- **MonetDB**：`MonetDb.Mapi` 不返回受影响行数，DML 的 `Execute` 固定为 0；测试以查询结果为准。
- **OpenTSDB**：依赖 HBase 与 JDK 8，链路最重；`tsd.core.auto_create_metrics=true` 已开启，metric/tag 不能含空白字符。
- **IPv4 服务**：VictoriaMetrics、InfluxDB 3、GreptimeDB 只监听 IPv4，配置中请用 `127.0.0.1`，不要用 `localhost`（Windows 会先尝试 `::1`）。
- **IoTDB REST**：需在 `conf/iotdb-system.properties` 保留 `enable_rest_service=true` 与 `rest_service_port=18080`。
- **仅开发机**：WSL 内服务以 root 运行，未做生产级隔离；生产环境仍按《数据库支持矩阵》的 CI 容器方案执行。
- **WSL 只读文件系统**：若出现 `Read-only file system`（本次部署遇到过一次），执行 `wsl --shutdown` 后重新启动 WSL，再 `sudo systemctl start localdb` 即可恢复，数据不会丢失。

## 七、本机安装器 Tools/localdb

C 盘空间紧张，数据库安装位置统一迁到空余最多的磁盘。当前布局：

- Windows 便携版：`E:\LocalDatabases`（apps/data/logs/state/downloads），由安装器自动选择空余最多的固定磁盘并记忆到 `%LOCALAPPDATA%\LocalDbTool\settings.ini`。
- WSL 虚拟磁盘：`E:\WSL\Ubuntu-24.04\ext4.vhdx`（约 97 GB），C 盘空余从 6.2 GB 提升到 109 GB。

```powershell
# 查看全部数据库、安装与运行状态
dotnet run Tools\localdb\localdb.cs -- list

# 启动：Windows 便携版未安装时自动联网下载并安装到空余最多磁盘
dotnet run Tools\localdb\localdb.cs -- start prometheus
dotnet run Tools\localdb\localdb.cs -- start tdengine
dotnet run Tools\localdb\localdb.cs -- stop prometheus
dotnet run Tools\localdb\localdb.cs -- status

# 维护
dotnet run Tools\localdb\localdb.cs -- clean        # Windows 下载残留与旧版本
dotnet run Tools\localdb\localdb.cs -- clean-wsl    # WSL apt/日志/安装包缓存与重复镜像
dotnet run Tools\localdb\localdb.cs -- wsl-move E:\WSL\Ubuntu-24.04 --yes
```

Windows 便携版与 WSL 委托分类：

| 运行方式 | 数据库 | 说明 |
|---------|--------|------|
| Windows 原生（zip 下载） | Prometheus、VictoriaMetrics、CockroachDB、MongoDB | 解压即用，隐藏进程启动，日志在 `logs/{id}.log` |
| WSL systemd | TDengine、Firebird | `systemctl start` |
| WSL Docker | ClickHouse、CrateDB、QuestDB | 容器缺失时自动 `docker run`，均 `restart=unless-stopped` |
| WSL 命令 | PrestoDB、Trino、MonetDB | `/opt/dbservers/*/bin/launcher start` 或 `monetdbd start` |
| 嵌入式 | DuckDB | 无服务，测试项目直接引用 NuGet |

> 仅 Windows 原生运行受限的数据库（ClickHouse、CrateDB、TDengine 服务端、Presto/Trino、HBase/OpenTSDB）继续走 WSL；本机未安装 Docker Desktop。

Presto 环境注意：`/opt/dbservers/presto-0.300` 需使用 JDK 17（`/usr/lib/jvm/java-17-openjdk-amd64`），且 `etc/config.properties` 的 `discovery.uri` 必须是 `http://127.0.0.1:8081`；写成 `localhost` 会解析到 `::1` 导致节点自检超时。安装器已通过 `presto-live.service` 常驻启动。
