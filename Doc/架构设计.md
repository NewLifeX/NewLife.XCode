# NewLife.XCode 架构设计

> 版本：v12.3 | 日期：2026-11-20

本文档描述 NewLife.XCode 的整体架构分层、核心组件及其协作关系。功能清单见[功能模块清单](功能模块清单.md)，需求定义见[需求文档](需求文档.md)。

---

## 1. 总体架构

XCode 采用**模型驱动 + 运行时元数据 + 多级缓存 + 可选分片**的分层架构，从上到下分为四层：

```
┌─────────────────────────────────────────────────┐
│                  应用层 (Application)              │
│  Entity<T>.Find/FindAll/Insert/Update/Delete     │
│  IQueryable<T> LINQ / DAL.Select<T>()             │
│  DbService HTTP 客户端                            │
├─────────────────────────────────────────────────┤
│              查询 DSL 层 (Query DSL)               │
│  WhereExpression / IQueryable<T> / SelectBuilder  │
│  WindowFunction / Pager / BatchFinder             │
├─────────────────────────────────────────────────┤
│              实体运行时层 (Entity Runtime)          │
│  EntitySession / EntityFactory / EntityOperate    │
│  EntityCache / SingleCache / FieldCache           │
│  EntityTransaction / DirtyCollection              │
│  IEntityInterceptor / NavigationLoader            │
│  EntityQueue / EntityDeferredQueue                │
├─────────────────────────────────────────────────┤
│          数据访问层 (DAL / Data Access Layer)      │
│  DAL / IDatabase / IDbSession / ConnectionPool    │
│  DbFactory / DriverLoader                          │
│  SelectBuilder / InsertBuilder / DbPackage        │
│  ReadWriteStrategy / SaveModes                    │
├─────────────────────────────────────────────────┤
│          数据库提供者层 (Database Providers)        │
│  SQLite / MySQL / SqlServer / Oracle / PG         │
│  达梦 / 金仓 / 瀚高 / DB2 / Hana / IRIS / VastBase │
│  TDengine / InfluxDB / ClickHouse / DuckDB        │
│  MongoDB / Network / NovaDb / SonnetDB / Access¹  │
│  SqlCe¹                                           │
└─────────────────────────────────────────────────┘
```

> ¹ Access 和 SqlCe 仅限 `NETFRAMEWORK`，当前未在 `DbFactory` 注册。

## 3. 关键流程

### 3.1 实体查询流程

```
Entity<T>.FindAll(whereExpression)
    → EntitySession.Query(where)
        → 尝试 Meta.Count 行数缓存（快速返回）
        → 尝试 EntityCache 整表缓存（<1000行）
        → 尝试 SingleCache 单对象缓存（主键查询）
        → 尝试 DbCache 数据层缓存（SQL 查询结果）
        → DAL.Session.Query(sql) 实际数据库查询
            → ConnectionPool.GetConnection()
            → DbCommand.ExecuteReader()
            → 实体映射 (EntityFactory.CreateEntity)
        → 写入各层缓存
```

### 3.2 实体写入流程

```
Entity.Insert/Update/Delete
    → IEntityInterceptor.OnXxx (AOP 前置钩子)
    → DirtyCollection 追踪变更字段
    → EntityTransaction 事务管理（如开启事务）
    → EntitySession.Insert/Update/Delete
        → DAL.Session.Execute(sql)
        → 写操作缓存失效/更新
    → IEntityInterceptor.OnXxx (AOP 后置钩子)
    → EntityQueue 异步批写（如启用）
```

### 3.3 自动迁移流程

```
应用启动 → Meta.Build(迁移模式)
    → EntityFactory.Init(entityType)
        → 加载 XML 模型 / Attribute 元数据
        → CheckModel() 校验模型一致性
        → CheckTable() 检查表结构
            → Migration.On: 自动建表/加字段/建索引
            → Migration.ReadOnly: 仅检查不修改
            → Migration.Off: 跳过
```

## 4. 关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 实体模型 | 充血模型 | 行为与数据不分离，Biz 分部类可扩展业务逻辑 |
| 缓存策略 | 多级阶梯缓存 | 读多写少场景优化，行数/整表/单对象/数据层四级递进 |
| 查询 DSL | 链式 WhereExpression + IQueryable LINQ | 既保留强类型链式 API，又兼容标准 LINQ 生态 |
| 模型驱动 | XML + Attribute 双通道 | XML 适合代码生成，Attribute 适合运行时元数据 |
| 分片策略 | 策略模式 (IShardPolicy) | 可扩展时间/哈希/范围等分片策略 |
| 数据库驱动 | 工厂模式 (DbFactory) | 按 DatabaseType 注册，按需创建驱动实例 |
| 反向工程 | 模板方法 (DbMetaData) | 正向（DDL 生成）和反向（Schema 读取）统一抽象 |
| 服务层 | DbService 四层架构 | 支持本地注入和 HTTP 远程调用两种部署模式 |
| 队列溢出抛错 | `EntityQueue` 满 `MaxEntity` 等待 15 秒仍满时抛 `XCodeException`，且不再先入队后报错 | 避免调用方误以为入队成功而重复写入 |
| 分片条件不足报错 | 时间分表推不出分片时抛 `XCodeException`，不再静默回落基准表 | 回落基准表会把其它分片的数据整体漏掉，故不设回退开关；确需跨分片查询时自行按时间枚举 `Shards(start, end)` |
| 零鉴权默认拒绝 | `DbService` 未配置令牌且未 `AllowAnonymous` 时，启动与登录都拒绝 | 端口一旦暴露，零鉴权等于把整库读写交给任何能连上的人；回退开关 `DbService.AllowAnonymous=true` |
| 令牌改请求头 | `DbClient` 不再把令牌放 GET 查询串，服务端优先读 `Authorization: Bearer`，兼容旧查询串 | 令牌不应进入代理与访问日志；服务端先升级即可兼容旧客户端 |
| SQL 日志脱敏 | 凭据类参数（口令/密钥/令牌）按 `LogMaskMode` 掩码后再落日志与异常 | 避免口令与令牌明文落盘；回退开关 `XCodeSetting.MaskSqlLog=false` |
| 备份路径囚笼 | 备份、恢复、数据包读写传入的文件名限定在 `NewLife.Setting.Current.BackupPath` 内 | 防 `../` 与绝对路径读写任意文件；无绕过开关，外部目录请改 `BackupPath` |
| 数据包未知表保护 | `DbPackage.RestoreAll` 默认只恢复目标库已有表或实体模型中的表 | 包内 XML 属于外部输入；跨库搬运显式传 `tables` 或 `AllowNewTables=true` |
| SQL 日志会话级抑制 | `DbPackage` 备份/恢复/同步用 `SetShowSql(false)` 只关本次会话日志 | 避免整进程 SQL 日志被关闭导致排障丢日志 |
| 排序位校验 | `PageParameter` 的排序子句拼入原生 SQL 前，只允许字段名与 Asc/Desc | 前端排序参数是盲注高发入口；非法内容抛 `XCodeException`，无误放开关 |
| 表名白名单 | `DbService.QueryCount` 只接受当前库已存在的表；MySQL/SQLServer 元数据查询转义单引号 | 表名来自远端调用方且会拼入元数据查询；动态表名调用方统一走实体模型 |
| 分表元数据无缓存回退 | `DAL.TableExists` 缓存未命中时查询无缓存元数据，分表路径统一使用 | 外部新建分表不应被 60 秒缓存窗口跳过；已有表仍走缓存 |
| 驱动下载不限制协议 | `DriverLoader` 直接使用配置的 http/https 源，不升级也不拒绝；下载后校验下载页哈希/固定 SHA-256/托管程序集 | 部分嵌入式工控机没有 OpenSSL，强制 https 或增加放行开关都会让驱动自举不可用；完整性校验不依赖传输层 |
| 配置缓存密钥沿用分类名 | `DbConfigProvider` 加密缓存密钥直接取配置分类名，不采用机器指纹/部署密钥派生 | 派生密钥挡不住能读本机的内部人，却牺牲跨机迁移与码神工具离线排查，且与 Core 的 `HttpConfigProvider`（AppId 作密钥）语义应一致；`Encrypted` 仅防明文落盘被直接读取 |
| 标识符引号由 `NameFormats.Exact` 表达 | `Exact` = 保持原样并强制加引号，`None` = 保持原样不加引号；KingBase/HighGo 默认 `Exact`，PostgreSQL/VastBase 默认 `Underline` | 引号行为与大小写语义此前散落在各 `FormatName` 重写里，`None` 对这些库无意义；收敛到枚举后，反向工程可按有效格式决定精确比较并在必要时自动 `RENAME COLUMN` |
| 同表禁止仅大小写不同的字段 | `TableItem.InitFields` 与反向工程均检测并抛 `XCodeException` | 大小写不敏感库无法区分、大小写敏感库语义混乱；不提供兼容开关，避免生成不可预期的 SQL |
| 改名保留过渡别名 | 内置实体改名后，旧属性名与旧查询方法以过时成员形式留在 `*.Biz.cs`，并跳过序列化与导出；旧查询方法直接转发到生成器产出的新名称方法 | 下游按编译警告迁移，而不是被编译错误一次性打断；别名不进入 `Fields` 与 `Table.Columns`，不会与真实字段混淆 |
| 多数据库能力模型 | 实例级 `DatabaseProfile` + `DatabaseCapability` flags；C# Attribute 只做静态默认值/文档来源 | 同一数据库在不同驱动、版本、连接配置下能力不同（MySql 驱动、SonnetDB 嵌入/远程、Presto 连接器、Readonly），静态特性无法表达 |
| 方言独立 | 新增可选 `IDbDialect`，暂不拆 `IDatabase` 门面 | 格式化/参数/分页/窗口函数有独立变更原因；先以可选接口接入，避免一次性破坏公共契约 |
| 非 SQL 数据库定位 | 能力标志 + 原生持久化适配器 + 原始命令；不新增 NoSQL 原生查询 DSL（N3） | 文档/时序数据库与关系模型的差异不能靠“补几个方法”消除；原生适配器只覆盖写入，驱动保持外置 |
| 窗口函数 | AST + `IDbDialect` 渲染 + 能力标志；默认不支持时抛异常，内存回退需显式开启 | 窗口函数方言差异大；字符串拼接无法判断能力与帧语义；内存回退只适合小结果集，必须由调用方显式承担代价 |
| DAL 边界 | DAL 及以上保持稳定；DAL 以下允许破坏性调整 | 实体层是主要使用面；把变更限制在 DAL 以下，可在不打断业务代码的前提下演进多数据库抽象 |

## 7. 待补充流程

以下关键流程需要人工补充序列图或详细说明：

- **DbService 远程调用序列**：客户端 → HTTP → DbController → DbServer → DbService → DAL → Database
- **二级缓存分布式协调**：应用 A 写操作 → CacheInvalidator → Redis 发布 → 应用 B 收到失效通知 → 清除本地缓存
- **EntityQueue 异步批写**：多线程 Insert → EntityQueue 缓冲 → 定时 Flush → 批量 SQL Merge
- **跨分片查询 (AutoShard)**：查询路由 → 各分片并行查询 → 结果聚合 → 排序/分页

## 8. 多数据库能力模型与方言抽象（已落地）

多数据库升级采用“保留三张门面 + 抽出可选接口”的渐进路线，详细切片与边界见 [M1-多数据库架构升级](M1-多数据库架构升级.md)。

核心决策：

- `IDatabase`/`IDbSession`/`IMetaData` 继续作为调用方入口，不一次性拆成十几个接口。
- 已新增 `IDbCapabilities`（能力标志/Profile）、`IDbDialect`（方言，`IDatabase.Dialect` 可访问）；元数据侧已拆出 `ISchemaReader`、`ISchemaMigrator`、`IDatabaseCreator`、`IDatabaseMaintenance`，`IMetaData` 保留组合门面。
- 能力 = 引擎能力 ∩ 当前连接配置 ∩ XCode 已实现范围；条件能力默认关闭，显式开启后再加标志。
- `BatchCapability` 已合并到 `DatabaseCapability.Bulk*`；`DAL.BatchCapabilities` 仅保留过渡别名。
- 有效迁移 = `Min(用户 Migration, Profile.MaxMigration)`；无 DDL 的提供者在配置层直接跳过。
- `EntityPersistence` 在拼 SQL 前检查 `Sql`/`Insert`/`Update`/`Delete` 能力，非 SQL 提供者失败信息明确。
- 非 SQL 数据库以“原始命令 + 批量写入”或“明确不支持”接入；实体 ORM 只承诺 SQL 提供者。
- 窗口函数采用 `WindowExpression` AST + `IDbDialect.RenderWindow` + `WindowFunctions`/`WindowFrame` 能力校验，默认不支持时抛异常；需要降级时显式开启 `WindowFallback.InMemory`，由 `WindowEvaluator` 在结果集上补算窗口列。
- 版本相关能力（DB2/达梦/HANA 的窗口能力）只在已经拿到 `ServerVersion` 后追加，不为了探测版本提前建立连接。
- 非 SQL 数据库通过 `IEntityPersistenceFactory` 注册原生持久化：InfluxDB 复用 Line Protocol 写入，MongoDB 通过 `IMongoDocumentWriter` 解耦驱动；关系型数据库回退到 SQL 持久化。
- DDL 入口通过 `DDLCommand` 类型化，`ISchemaMigrator.GetCommandSql/ExecuteCommand` 为正式入口；旧 `DDLSchema + Object[]` 保留兼容转发。
